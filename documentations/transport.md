# ТЗ: Этап 3. Создание транспорта (Модальное окно и валидация)

**Проект:** «Терра-Хоппер Онлайн» (Django + HTMX)  
**Фокус этапа:** Реализация модального окна создания транспорта с валидацией полей, отображением неизменяемых характеристик по умолчанию и сохранением в БД.

---

## 1. Концепция и UI/UX модального окна

При клике на кнопку **«+ Создать транспорт»** на главной странице (Dashboard) должно открываться интерактивное модальное окно (Modal).

### 1.1. Внешний вид модального окна
1. **Шапка / Изображение:**
   * В верхней части модального окна располагается статичное изображение транспорта.
   * Тег `<img>` ссылается на статичный файл (например, `{% static 'images/terra-hopper.png' %}`). Путь к файлу передается отдельным ресурсом.
2. **Форма ввода (Настраиваемые поля):**
   * **`name` (Имя транспорта):** Текстовое поле ввода (`<input type="text">`). Обязательное.
   * **`mass_kg` (Масса):** Числовое поле ввода (`<input type="number" step="0.1">`). Обязательное. Допустимый диапазон: `100.0` … `500.0` кг. Подсказка в интерфейсе о разрешенном диапазоне.
3. **Неизменяемые характеристики (Значения по умолчанию / Read-Only):**
   * Данные поля отображаются **только как информационный текст / неактивные плашки**, БЕЗ элементов `<input>` (гарантирующими невозможность переопределения):
     * **Начальный запас силы (`strength`):** `100.0 %`
     * **Начальная энергия реактора (`reactor_energy`):** `100.0 %`
     * **Начальное положение (`location_state`):** `На поверхности (surface)`
     * **Начальная дистанция (`distance`):** `0.0 м`
4. **Кнопки управления:**
   * Кнопка **«Отмена»** (закрывает модальное окно без отправки формы).
   * Кнопка **«Создать»** (отправляет данные формы на бэкенд).

---

## 2. Логика HTMX / Django Form

### 2.1. Открытие модального окна
* Кнопка «+ Создать транспорт» отправляет HTMX GET-запрос: `hx-get="{% url 'hopper:create_modal' %}"` с указанием целевого контейнера для вставки модального окна (`hx-target="#modal-container"`).
* Django View возвращает HTML-фрагмент с разметкой модального окна.

### 2.2. Валидация и обработка формы
Форма отправляет HTMX POST-запрос на URL создания транспорта (`/hopper/create/`):
* **Серверная валидация по ТЗ:**
  * Если `name` пустой или состоит только из пробелов — `ValueError("Имя не может быть пустым.")`.
  * Если `mass_kg` вне диапазона `100.0`…`500.0` — `ValueError("Масса должна быть в диапазоне 100.0…500.0 кг.")`.
* **При ошибке валидации:**
  * Сервер возвращает модальное окно с отображением сообщения об ошибке под соответствующим полем или вверху формы (с кодом состояния `400 Bad Request` / `422 Unprocessable Entity`), чтобы HTMX обновил форму без перезагрузки всей страницы.
* **При успешном создании:**
  * Создается экземпляр `Hopper` в БД с привязкой к текущему `request.user`.
  * Сервер возвращает заголовок `HX-Trigger: hopperCreated` (или обновленный фрагмент списка имеющегося транспорта в гараже).
  * Модальное окно закрывается, а карточка нового транспорта появляется в списке имеющегося транспорта пользователя без полной перезагрузки страницы.

## 3. Требования к бэкенду (Django View & Service)

В `apps/hopper/services.py` реализовать функцию/метод создания транспорта:

```python
def create_hopper_for_user(user, name: str, mass_kg: float) -> Hopper:
    # Очистка имени от внешних пробелов
    clean_name = name.strip() if name else ""
    if not clean_name:
        raise ValueError("Имя не может быть пустым.")
    
    try:
        mass_val = float(mass_kg)
    except (ValueError, TypeError):
        raise ValueError("Масса должна быть числом.")
        
    if not (100.0 <= mass_val <= 500.0):
        raise ValueError("Масса должна быть в диапазоне 100.0…500.0 кг.")
        
    return Hopper.objects.create(
        user=user,
        name=clean_name,
        mass_kg=mass_val,
        strength=100.0,
        reactor_energy=100.0,
        location_state="surface",
        distance=0.0
    )
```
