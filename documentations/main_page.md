Вся доменная логика и модели транспорта/результатов должны размещаться в приложении `apps/hopper` (или `apps/transport`).

```
apps/
└── hopper/
    ├── domain/               # Чистая бизнес-логика из 1-й практики
    │   ├── exceptions.py     # Иерархия ошибок (TerraHopperError и др.)

    ├── models.py             # Django ORM модели (Hopper, Leaderboard / TripResult)

    ├── urls.py               # Маршруты
    └── templates/
        └── hopper/
            └── dashboard.html

```

## 2. Модель данных (Django ORM)

### 2.1. Модель `Hopper` (Транспорт)

Создать модель `Hopper` в `apps/hopper/models.py`:

```python
class Hopper(models.Model):
    user = models.ForeignKey(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name="hoppers",
        verbose_name="Владелец"
    )
    name = models.CharField(max_length=255, verbose_name="Имя транспорта")
    mass_kg = models.FloatField(verbose_name="Масса (кг)")
    strength = models.FloatField(default=100.0, verbose_name="Запас силы (%)")
    reactor_energy = models.FloatField(default=100.0, verbose_name="Энергия реактора (%)")
    location_state = models.CharField(
        max_length=20,
        choices=[("surface", "На поверхности"), ("underground", "Под землей")],
        default="surface",
        verbose_name="Положение"
    )
    distance = models.FloatField(default=0.0, verbose_name="Пройденная дистанция (м)")
    best_distance = models.FloatField(default=0.0, verbose_name="Рекордная дистанция (м)")
    created_at = models.DateTimeField(auto_now_add=True, verbose_name="Дата создания")

    def __str__(self):
        return f"{self.name} ({self.user.username})"

```

**Валидация по ТЗ при создании (в clean() / save() или сервисе):**

* `name`: непустая строка (без пробелов по краям). Ошибка `ValueError("Имя не может быть пустым.")`.
* `mass_kg`: диапазон `100.0` … `500.0`. Ошибка `ValueError("Масса должна быть в диапазоне 100.0…500.0 кг.")`.
* `strength`: диапазон `0.0` … `100.0`. Ошибка `ValueError("Сила должна быть в диапазоне 0…100.")`.
* `reactor_energy`: диапазон `0.0` … `100.0`. Ошибка `ValueError("Энергия реактора должна быть в диапазоне 0…100.")`.

## 4. Требования к UI и Дашборду (`/dashboard/` или `/`)

После успешного входа пользователь перенаправляется на главный экран. Главная страница должна содержать 3 ключевых блока:

### 4.1. Блок 1: Турнирная таблица (Leaderboard)

Отображает топ лучших результатов пользователей по пройденной дистанции.

* **Таблица из 3 колонок:**
1. Ник пользователя (`user.username`)
2. Имя транспорта (`hopper.name`)
3. Лучший результат (`best_distance` в метрах)


* Таблица формируется запросом к БД: выводится топ-10/топ-20 записей с максимальной `best_distance`.
* Если у пользователей еще нет заездов/транспорта, отображается заглушка: *«Турнирная таблица пока пуста»*.

### 4.2. Блок 2: Панель создания (Кнопка)

* Наглядная кнопка **«+ Создать транспорт»**.
* **ВАЖНО:** На этом этапе кнопка должна быть чисто визуальным элементом UI (заглушкой) или вести на модальное окно/пустой роут без бизнес-обработки. Нажатие не должно ломать страницу.

### 4.3. Блок 3: Список транспорта пользователя (Гараж)

* Секция со списком всех транспортных средств, принадлежащих текущему авторизованному пользователю (`request.user.hoppers.all()`).
* Для каждого транспорта выводится карточка с базовой информацией:
* Имя транспорта (`name`)
* Масса (`mass_kg` кг)
* Текущий статус: Сила (`strength`), Энергия реактора (`reactor_energy`), Положение (`location_state`), Дистанция (`distance`).


* Если у пользователя еще нет транспорта, выводится сообщение: *«У вас пока нет созданного транспорта. Нажмите "Создать транспорт", чтобы начать!»*.
